## 1. Критические ошибки потери данных и синхронизации (`shared` / `server` / `client`)

- [ ] **1. Невозможность сбросить поля `L`, `x`, `y`, `D`, `s`, `A`, `c` в MongoDB (возврат старых значений после перезагрузки)**
  - **Где:** [INodeDB.ts](file:///d:/_sites/a-node(v.AI)/shared/types/INodeDB.ts#L66-L80), [INodeDB.ts](file:///d:/_sites/a-node(v.AI)/shared/types/INodeDB.ts#L228-L265), [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L312-L318)
  - **Ошибка:** `bulkSaveNodes` формирует `$unset` только при `value === null`, а `toDB()` при очистке списка (`L`), координат (`x`, `y`), повторов (`D`), флагов (`s`, `A`) и клона (`c`) возвращает `undefined`, который вырезается `JSON.stringify` при отправке по сети. В итоге старые значения навсегда остаются в БД.
  - **Исправление:** В `TPackedData.pack()` и `toDB()` возвращать `null` вместо `undefined` для сброшенных полей.

- [ ] **2. Потеря несохранённых мутаций на клиенте при HTTP-ошибках сервера (`500`/`502`/`503`/`400`)**
  - **Где:** [api.ts](file:///d:/_sites/a-node(v.AI)/client/src/features/core/api.ts#L83-L112), [serverPersistence.ts](file:///d:/_sites/a-node(v.AI)/client/src/features/core/serverPersistence.ts#L220-L273)
  - **Ошибка:** `api.saveNodes`, `api.deleteNode` и `api.deleteNodesBatch` не проверяют `if (!response.ok)` и не выбрасывают исключение при ответах 4xx/5xx, из-за чего `ServerPersistence.save()` считает отправку успешной и очищает `dirtyNodes` и `pending_mutations` в IndexedDB.
  - **Исправление:** В `api.saveNodes`, `api.deleteNode` и `api.deleteNodesBatch` выбрасывать `new Error(\`HTTP \${response.status}\`)` при `!response.ok`.

- [ ] **3. Гонка состояний (Race Condition) при смене доски: перезапись кэша чужой доски и рендер чужих нод**
  - **Где:** [serverPersistence.ts](file:///d:/_sites/a-node(v.AI)/client/src/features/core/serverPersistence.ts#L107-L110), [serverPersistence.ts](file:///d:/_sites/a-node(v.AI)/client/src/features/core/serverPersistence.ts#L143-L176), [serverPersistence.ts](file:///d:/_sites/a-node(v.AI)/client/src/features/core/serverPersistence.ts#L355-L364), [serverPersistence.ts](file:///d:/_sites/a-node(v.AI)/client/src/features/core/serverPersistence.ts#L403-L454), [serverPersistence.ts](file:///d:/_sites/a-node(v.AI)/client/src/features/core/serverPersistence.ts#L483-L495)
  - **Ошибка:** `ServerPersistence.unmount()` не очищает `debounceTimer` и не помечает инстанс размонтированным: при переходе с доски A на доску B таймер доски A сохраняет ноды доски B в кэш доски A, а запоздавшие ответы `load()`/`applyDelta()` доски A рендерят ноды на доске B.
  - **Исправление:** Ввести флаг `isUnmounted`, очищать `debounceTimer` в `unmount()`, проверять `if (this.isUnmounted || core.serverPersistence !== this) return;` после асинхронных вызовов.

- [ ] **4. Пропуск изменений при дельта-синхронизации из-за клиентского `lastUpdate` и позднего расчёта `serverTime`**
  - **Где:** [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L56-L59), [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L207), [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L297), [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L335-L339)
  - **Ошибка:** `bulkSaveNodes` перезаписывает `lastUpdate` значением с часов клиента (и падает с `CastError` при невалидной дате), а `getNodesAndPageByNodeId` фиксирует `serverTime` после выполнения всех запросов к БД.
  - **Исправление:** В `bulkSaveNodes` принудительно ставить серверный `setFields.lastUpdate = now;`, а в `getNodesAndPageByNodeId` фиксировать `serverTime` до начала запросов к БД.

- [ ] **5. Неработающая дельта-синхронизация клонов между разными досками по SSE**
  - **Где:** [node.controller.ts](file:///d:/_sites/a-node(v.AI)/server/src/controllers/node.controller.ts#L108-L132), [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L36-L59), [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L184-L204)
  - **Ошибка:** При изменении оригинала ноды на доске 1 сервер шлёт `nodes_updated` на доску 2 (где находится клон), но дельта-запрос доски 2 фильтрует `{ pageId: desk2, lastUpdate: { $gt: since } }` — у самого клона `lastUpdate` не менялся, поэтому возвращается `nodes: []`.
  - **Исправление:** При обновлении ноды обновлять `lastUpdate: now` у её клонов (`Node.updateMany({ c: { $in: nodeObjectIds } }, { $set: { lastUpdate: now } })`).

- [ ] **6. Три ошибки синхронизации OUT-фреймов: затирание битов `s`, коллизия `lID` в дельте и «призрачные» удалённые ноды**
  - **Где:** [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L82-L88), [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L115-L125), [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L166-L170)
  - **Ошибка:** Запись `deskPageNode.s = pageDeskLID` затирает старшие биты флагов `s`; при `isDelta === true` `maxLID` считается по пустой дельте (`0`), вызывая коллизию `lID = 1`; удалённые в корзину (`inTrash: true`) дочерние ноды вложенной доски не приходят в дельте и остаются висеть на родительской доске; в `copy.L` возможен знаковый overflow без `>>> 0`.
  - **Исправление:** Сохранять старшие биты `((deskPageNode.s || 0) & ~0x1ffff) | (pageDeskLID & 0x1ffff)`, считать `maxLID` по всей доске, включать удалённые ноды при `isDelta` и использовать `>>> 0` для `copy.L`.

  - **Где:** [node.controller.ts](file:///d:/_sites/a-node(v.AI)/server/src/controllers/node.controller.ts#L170-L232), [node.service.ts](file:///d:/_sites/a-node(v.AI)/server/src/services/node.service.ts#L378-L391)

- [ ] **8. Ошибки битовой упаковки/распаковки в `INodeDB`: искажение дат до `2026-10-13`, знаковый сдвиг и несброс старых полей в `fromDB`**

- [ ] **11. Очистка очереди мутаций в `flushSync()` (`beforeunload`) до подтверждения доставки и падение при payload > 64 КБ**
