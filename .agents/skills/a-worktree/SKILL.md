# Управление git worktree (/a-worktree)

Регламент создания изолированных рабочих деревьев (worktree), их последующего слияния с основной веткой и очистки.

## Ограничения

1. Директории worktree размещаются строго на уровень выше основного проекта: `../a-node-wt-<имя>`. Ветка именуется с префиксом `a-node-wt-<имя>`.
2. Запрещено принудительно удалять ветку (`git branch -D`), если слияние не завершено или есть несохранённые изменения, без прямого указания пользователя.
3. При возникновении конфликтов слияния немедленно останавливать процесс, выводить список конфликтных файлов и ждать инструкций пользователя.
4. Минимальный вывод: только команды, статус и ссылки на затронутые файлы.

## Аргументы и триггеры

- `создай новую ветку <имя>` / `/a-worktree new <имя>`: создание ветки и папки worktree.
- `обновить из главной` / `/a-worktree update-from-main [имя]`: перенос изменений из `main` в ветку worktree с разрешением конфликтов и исправлением ошибок.
- `подтяни из основной` / `/a-worktree sync [имя]`: подтягивание актуальных изменений из `main` в ветку worktree.
- `слей с основной` / `/a-worktree merge [имя]`: коммит, слияние ветки в `main`, удаление worktree и ветки.
- `/a-worktree list`: список текущих worktree.
- `/a-worktree abort`: отмена текущего слияния при конфликтах (`git merge --abort`).

## Порядок действий

### 1. Создание новой ветки worktree (`new <имя>`)

1. Проверить имя базовой ветки (по умолчанию `main`):
   ```bash
   git branch --show-current
   ```
2. Сформировать имя ветки `a-node-wt-<имя>` и путь к рабочей директории: `../a-node-wt-<имя>`.
3. Создать worktree с новой веткой:
   ```bash
   git worktree add ../a-node-wt-<имя> -b a-node-wt-<имя>
   ```
4. При наличии незакоммиченных агентов/скилов в `.agents/` основного репозитория — скопировать их в каталог worktree.
5. Вывести подтверждение с указанием имени ветки и абсолютного пути к новому каталогу.

### 2. Синхронизация с основной веткой (`sync [имя]`)

1. **Проверка состояния worktree:**
   - Определить директорию worktree (текущую или `../a-node-wt-<имя>`).
   - Проверить чистоту рабочего дерева:
     ```bash
     git -C <путь_к_worktree> status --porcelain
     ```
   - При наличии незакоммиченных изменений предложить пользователю закоммитить их перед слиянием.
2. **Слияние из main:**
   - Выполнить слияние актуального состояния `main` в ветку worktree:
     ```bash
     git -C <путь_к_worktree> merge main
     ```
3. **Обработка конфликтов:**
   - При возникновении конфликтов остановить процесс, вывести список конфликтных файлов:
     ```bash
     git -C <путь_к_worktree> diff --name-only --diff-filter=U
     ```
   - Запросить решение пользователя или предложить `/a-worktree abort`.
4. **Верификация типов:**
   - Запустить валидацию типов в директории worktree:
     ```bash
     npm --prefix <путь_к_worktree>/client run typecheck
     ```

### 3. Обновление из главной с исправлением ошибок (`update-from-main [имя]` / `обновить из главной`)

1. **Проверка состояния worktree:**
   - Определить целевой каталог worktree (текущий или `../a-node-wt-<имя>`).
   - Проверить наличие незакоммиченных изменений:
     ```bash
     git -C <путь_к_worktree> status --porcelain
     ```
   - Закоммитить текущие изменения перед слиянием, чтобы избежать потери данных.
2. **Слияние из main:**
   - Выполнить слияние актуального состояния ветки `main`:
     ```bash
     git -C <путь_к_worktree> merge main
     ```
3. **Устранение конфликтов:**
   - При наличии конфликтов вывести список файлов:
     ```bash
     git -C <путь_к_worktree> diff --name-only --diff-filter=U
     ```
   - Прочитать конфликтующие файлы, разрешить маркеры конфликтов, сохранив функционал обеих веток.
   - Добавить разрешённые файлы в индекс:
     ```bash
     git -C <путь_к_worktree> add <файлы>
     ```
4. **Исправление ошибок и typecheck:**
   - Запустить проверку типов:
     ```bash
     npm --prefix <путь_к_worktree>/client run typecheck
     ```
   - При ошибках типов или компиляции проанализировать диагностику и внести минимальные точечные исправления.
   - Повторять typecheck до полного прохождения без ошибок.
5. **Завершение слияния:**
   - Зафиксировать коммит слияния:
     ```bash
     git -C <путь_к_worktree> commit -m "chore: merge main and fix errors"
     ```

### 4. Слияние с основной веткой (`merge [имя]`)

1. **Проверка изменений в worktree:**
   - Если имя ветки не указано, определить активное worktree через `git worktree list`.
   - Проверить наличие незакоммиченных изменений в `../a-node-wt-<имя>`:
     ```bash
     git -C ../a-node-wt-<имя> status --porcelain
     ```
   - Если есть незакоммиченные файлы — закоммитить их с осмысленным сообщением или запросить подтверждение.
2. **Переход и слияние:**
   - Убедиться, что в основном репозитории активна ветка `main`:
     ```bash
     git checkout main
     ```
   - Выполнить слияние:
     ```bash
     git merge a-node-wt-<имя>
     ```
3. **Обработка конфликтов:**
   - Если слияние завершилось ошибкой `CONFLICT`:
     - Получить список файлов с конфликтами:
       ```bash
       git diff --name-only --diff-filter=U
       ```
     - Вывести пользователю список конфликтующих файлов и остановить выполнение.
     - Совместно с пользователем устранить конфликты, затем выполнить `git commit`.
4. **Очистка (после успешного слияния):**
   - Удалить worktree:
     ```bash
     git worktree remove ../a-node-wt-<имя>
     ```
   - Удалить локальную ветку:
     ```bash
     git branch -d a-node-wt-<имя>
     ```
   - При необходимости удалить оставшуюся пустую папку `../a-node-wt-<имя>`.

### 5. Верификация

1. Проверить чистоту списка worktree:
   ```bash
   git worktree list
   ```
2. Проверить статус ветки `main`:
   ```bash
   git status
   ```
3. Выполнить валидацию типов основного проекта:
   ```bash
   npm --prefix client run typecheck
   ```
