# Вёрстка и импорт из Figma (/a-figma)

Регламент изолированного переноса макетов и UI-компонентов из Figma в кодовую базу `a-node_2.0`.

## Ограничения

1. Запрещено выгружать в основной контекст сырые дампы JSON деревьев узлов Figma.
2. Использовать строгие TypeScript типы без `any` и параметр-свойств в конструкторах (`erasableSyntaxOnly`).
3. Стилизация компонентов — через SCSS-модули или scoped стили по соглашениям проекта.
4. Минимальные точечные правки: не переписывать существующие ноды и стили целиком.

## Входные данные (Аргументы)

- `$1` (Figma URL / Node ID): ссылка на макет или конкретный узел фрейма/компонента.
- `$2` (Целевой путь / Компонент): имя создаваемого компонента или путь в `client/src/`.

## Пошаговый алгоритм

### 1. Подготовка контекста и валидация ввода
1. Если ссылка на Figma не передана — запросить: *"Предоставьте ссылку на макет Figma или node-id компонента"*.
2. Определить целевой каталог для компонента (например, в `client/src/features/nodes/` или `client/src/components/`).

### 2. Извлечение дизайн-контекста
1. Вызвать инструмент `call_mcp_tool` сервера `figma_figma` (`get_design_context` / `get_screenshot`) для целевого узла.
2. Извлечь только значимые данные:
   - Цветовые токены, отступы, типографику, размеры и flex/grid параметры.
   - Иерархию вложенности элементов.

### 3. Генерация кода компонента
1. Создать/обновить файл разметки и стилей по стандартам проекта (нативный Web Component или TypeScript модуль с SCSS).
2. Привязать CSS-переменные проекта вместо жестко захардкоженных hex-значений там, где это применимо.

### 4. Верификация
1. Выполнить проверку типов: `npm --prefix client run typecheck`.
2. Вывести кликабельную ссылку на созданный файл и компактное резюме в 1 предложение.
