# Пошаговая сборка теста Vitest

Скилл для создания каркаса и пошаговой сборки модульного теста без лишних запусков тестового раннера.

## Правила и ограничения

1. Запрещен полный прогон тестов. Запуск строго таргетированный (`npx vitest run <target.test.ts>`).
2. Все описания (`describe`, `it`, `test`) писать строго на русском языке.
3. TypeScript: соблюдать `erasableSyntaxOnly` (без enum и без parameter properties).

## Процесс работы

### Этап 1: Выбор файла и инициализация
При запросе создания теста для `<Класс|Модуль>`:
1. Найти существующие тестовые файлы для объекта (в подпапке `__tests__` или рядом).
2. Если файлы найдены и пользователь явно не указал действие в промпте (создать новый файл или дополнить), спросить через `ask_question`: создать новый файл теста или дополнить существующий.
3. Варианты действий:
   - **Дополнение существующего:** открыть найденный файл и дописать новый `describe` или `it` без перезаписи существующего кода.
   - **Создание нового:** создать `<target>.test.ts` на основе заготовки `./resources/test-template.ts` (заменить `{{TARGET_NAME}}` на целевой класс, добавить импорт тестируемого модуля).
4. Не запускать Vitest на этом этапе.

### Этап 2: Пошаговая сборка
1. Каждая последующая реплика пользователя переводится строго в строки теста (arrange-act-assert).
2. Минимальные точечные правки без переписывания файла.
3. Не запускать Vitest автоматически.
4. Готовые шаблоны кода брать строго из [resources/snippets.md](file:///d:/_sites/a-node(v.AI)/.agents/skills/a-create-test/resources/snippets.md) без поиска по проекту.

### Этап 3: Проверка и отладка
1. Запуск Vitest выполняется строго по команде `!проверь` или «реализуй тест»:
   ```bash
   npm --prefix client test -- <target.test.ts>
   ```
2. Команда «реализуй тест»: прогнать тест, при ошибке — отладить и исправить основную программу до успешного прохождения теста.
