## 1. Архитектурный и компонентный обзор

### 1.1. Суть и назначение системы
`a-nodes` — это гибрид бесконечной визуальной доски (Infinite 2D Canvas) и древовидного аутлайнера (Spatial Outliner). Проект решает задачу гибкого визуального мышления и управления знаниями/задачами с уникальными механиками:
1. **Иерархические деревья с выравниванием по вертикали и отступам** (`GRID.x = 50px`).
2. **Фреймы и подфреймы** (`TFrame`), соединенные динамическими SVG-кривыми Безье (`Ge_Path`).
3. **Клоны с синхронизацией в реальном времени** (`LNode_TEClone` + `TClones`), позволяющие проецировать задачи из одного фрейма в другой с автоматическим отображением родительского пути и относительного рейтинга/позиции.
4. **Ультра-компактная битовая сериализация в БД** (`TPackedData`), пакующая иерархию, режимы повторов и связи в битовые маски целых чисел.

### 1.2. Структура монорепозитория
- **`client/`**: SPA на чистом TypeScript (без тяжелых фреймворков вроде React/Vue), сборщик Vite, SCSS для стилей. Прямое управление DOM-узлами и SVG-слоем для максимальной скорости отрисовки.
- **`server/`**: Node.js + Express 5, MongoDB (Mongoose), JWT-авторизация, Google Identity Service, Telegram Bot (`telegraf`).
- **`shared/`**: Общие TypeScript-типы и алгоритмы сериализации (`INodeDB.ts`, `ILNode.ts`, `IUser.ts`).
- **`_base/`**: Внешний Git-субмодуль с базовыми утилитами (Router, EventEmitter, иконки).

### 1.3. Ключевые архитектурные паттерны
- **Model-View Separation**: `LNode` (логика, координаты, данные) отделен от `VNode` (DOM-представление, стили, обработчики событий мыши).
- **Event-Driven Bus**: Централизованный `Store` (на базе `EventEmitter`), связывающий менеджеры, рендерер и сохранение.
- **Debounced Server Persistence**: Локальные изменения мгновенно отражаются в памяти и на холсте, затем накапливаются в `dirtyNodes` и сохраняются пачками через `bulkWrite` с дебаунсом 1000мс.

## 2. Анализ критических уязвимостей и скрытых проблем

В ходе глубокого исследования кодовой базы были выявлены следующие архитектурные и критические дефекты:

1. **Критическая уязвимость изоляции данных (Multi-tenancy / Security)**:
   - В `server/src/controllers/node.controller.ts` методы `getNodesByParentNodeId`, `saveNodesController` и `deleteNodeController` **не фильтруют данные по `userId` текущего авторизованного пользователя**.
   - Любой аутентифицированный пользователь может запросить, перезаписать (`$set`) или удалить (`findByIdAndDelete`) чужие ноды, зная или перебрав их идентификаторы.
2. **Несоответствие индексов MongoDB схеме модели**:
   - В `server/src/models/Node.ts` (строка 58) объявлен индекс: `nodeSchema.index({ ownerId: 1, pageId: 1 })`.
   - В схеме `Node` поле называется `userId`, а не `ownerId`. Индекс строится по несуществующему полю и не ускоряет реальные выборки.
3. **Уязвимость XSS при выводе текста нод**:
   - В `VTextEdit.render()` и `VTextEditClone.render()` текст вставляется напрямую в `innerHTML`:
     ```ts
     const str = title.replace(/\n/g, "<br/>");
     this.titleEl.innerHTML = str;
     ```
   - Отсутствует экранирование спецсимволов HTML (`<`, `>`, `&`, `"`). Если в заголовке ноды окажется HTML/JS (например, при импорте, совместной работе или через буфер обмена), выполнится произвольный скрипт.
4. **Переполнение 32-битного знакового целого в `TPackedData`**:
   - В `blockL` (`INodeDB.ts`) поле `parentLID` (17 бит) сдвигается на 15 бит (`offset = 15`). Сумма битов: $15 + 17 = 32$.
   - В JavaScript побитовые операторы (`<<`, `>>`, `|`) работают с 32-битными знаковыми числами (`Int32`). Установка 32-го бита превращает результат в отрицательное число, что приводит к искажению данных в БД при больших ID.
5. **Рассинхронизация запроса повторов с новым форматом БД**:
   - В `getNodesByParentNodeId` сервер ищет ноды по условию: `{ "exData.repeatDay": { $lt: new Date() } }`.
   - Однако логика повторов была мигрирована в битовое поле `D` (`TRepeatMode`), поэтому ноды в новом формате этим фильтром не выбираются.
6. **Подавление ошибок записи на бэкенде**:
   - В `saveNodes` блок `catch (err)` возвращает `null`, не логируя стек и отдавая клиенту статус 200 с пустыми ID, что маскирует сбои MongoDB.
7. **Атавизмы и устаревший код в Telegram-боте**:
   - В `server/src/bot.ts` остался неиспользуемый код трекера веса (`liner.esho.uz`, «присылай свой вес») из старого проекта автора, который не имеет отношения к задачам `a-nodes`.
8. **Неполная реализация Undo/Redo (History)**:
   - `core.history.execute()` вызывается исключительно при окончании drag-and-drop перемещения ноды. Создание, удаление, редактирование текста, смена родителя и вставка из буфера в историю не пишутся.
9. **Закомментированные горячие клавиши и опечатка в имени файла**:
   - Файл `client/src/features/core/comands.ts` содержит опечатку в названии (вместо `commands.ts`). Команды дублирования (`Ctrl+D`), авто-выравнивания (`Alt+Q`, `Alt+W`, `Alt+E`) и сортировки закомментированы.

## 3. Топ-20 рекомендаций по улучшению проекта (Refactoring, Architecture & Security)

### 1. Защита мультитенантности и прав доступа (Security)
Внедрить жесткую проверку прав во всех контроллерах `server/src/controllers/node.controller.ts`:
- В `getNodesByParentNodeId`: добавить фильтр `{ userId: req.user.id }`.
- В `saveNodes`: принудительно выставлять `node.userId = req.user.id`, а в операциях `updateOne` обновлять только записи с соответствующим `userId`.
- В `deleteNodeController`: удалять с условием `{ _id: id, userId: req.user.id }`.

### 2. Исправление индекса в Mongoose
В `server/src/models/Node.ts` исправить определение составного индекса:
```ts
nodeSchema.index({ userId: 1, pageId: 1, inTrash: 1 });
```
Это ускорит выборку рабочего стола в разы при росте базы.

### 3. Защита от XSS (Sanitization)
Использовать безопасную вставку текста через `textContent` либо утилиту экранирования перед заменой переносов строк:
```ts
function escapeHtml(str: string): string {
  return str.replace(/[&<>"']/g, (m) => ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' })[m]!);
}
this.titleEl.innerHTML = escapeHtml(title).replace(/\n/g, "<br/>");
```

### 4. Исправление переполнения битовых масок (`TPackedData`)
Перейти на `BigInt` внутри `TPackedData` либо перераспределить биты (например, ограничить `index` до 8 бит — 256 детей в одной ветке более чем достаточно, высвободив биты под `parentLID` без выхода за 30 бит).

### 5. Полноценная реализация Command Pattern для Undo/Redo
Расширить `History` командами для всех действий:
- `CreateNodeCommand`, `DeleteNodeCommand`, `EditTitleCommand`, `ChangeIndentCommand`, `ReparentCommand`.
- Активировать вызов `command.execute()` внутри `core.history.execute()`.

### 6. Переработка Telegram-бота под архитектуру a-nodes
Удалить код учета веса из `server/src/bot.ts`. Реализовать:
- Прием входящих мыслей/задач через Telegram и создание нод во входящем списке (`Inbox` / root desk).
- Отправку утренних и вечерних напоминаний по нодам, у которых наступила дата в `repeatMode`.

### 7. Рефакторинг и актуализация команд (`comands.ts` -> `commands.ts`)
- Исправить название файла на `commands.ts`.
- Раскомментировать и адаптировать команду дублирования (`Ctrl+D`), алгоритмы упорядочивания (`Alt+Q/W/E`) и модалку сортировки.

### 8. Оптимизация поиска нод с датами повтора
Хранить дату следующего повтора (`nextDate`) в явном виде в схеме `Node` с индексом `{ userId: 1, nextDate: 1 }` вместо попыток декодировать упакованное битовое поле `D` при поиске на сервере.

### 9. Корректная обработка ошибок и транзакции на бэкенде
- В `saveNodes` логировать ошибки через `console.error` и пробрасывать их наружу с кодом 500.
- Для критических операций пакетного обновления использовать транзакции MongoDB (`session.withTransaction()`).

### 10. Декомпозиция монолитного объекта `core`
Разделить `client/src/features/core/core.ts` на изолированные модули:
- Вынести управление режимами мыши и жестов в `InputStateManager`.
- Использовать понятный Dependency Injection или контекст вместо глобальных мутаций полей `core.mode`.

### 11. Виртуализация / пространственный куллинг (Spatial Culling)
При росте холста свыше 500-1000 узлов одновременный рендеринг всех DOM-нод вызывает просадки FPS.
- Добавить проверку пересечения `node.getNodeRect()` с областью видимости экрана (`viewport.getBounds()`).
- Скрывать узлы вне экрана (`display: none` или удаление из DOM с сохранением в памяти).

### 12. Двусторонняя синхронизация в реальном времени (WebSockets / SSE)
В настоящее время сохранение происходит односторонними PUT-запросами.
- Внедрить Socket.io или Server-Sent Events (SSE) для мгновенного обновления холста при работе в нескольких вкладках или с разных устройств (десктоп + телефон).

### 13. Валидация входных данных на сервере (Zod)
Внедрить схему валидации DTO для входящих запросов (сохранение нод, регистрация, привязка Telegram), предотвращая запись некорректных типов данных в MongoDB.

### 14. Мобильная адаптация и экранная клавиатура
- Улучшить поведение при открытии виртуальной клавиатуры на iOS/Android (учет `window.visualViewport` при автофокусе на `contenteditable`).
- Добавить плавающую панель мобильных действий (Add child, Outdent, Indent, Delete) над клавиатурой.

### 15. Устранение типов `any` и включение Strict Mode
В проекте присутствуют конструкции `as any` и `any[]` в `NodeManager.ts`, `comands.ts`, `node.controller.ts`. Заменить их на строгие дженерики и типы `ILNode` / `INodeDB`.

### 16. Централизованный логгер для продакшна
Заменить разрозненные вызовы `console.log` на легковесный логгер с уровнями `debug / info / warn / error` и фильтрацией в production-сборке.

### 17. Модульное и интеграционное тестирование
- Настроить **Vitest** для `client/` и `shared/` (тестирование упаковки `TPackedData`, алгоритма перестроения дерева `TList.checkTree`, связей фреймов).
- Настроить **Supertest** для эндпоинтов `server/`.

### 18. Интерфейс корзины (Trash Bin UI)
В базе данных есть флаг `inTrash: true` и скрипт `clearTrash.ts`, но в пользовательском интерфейсе нет возможности просмотреть корзину, восстановить ошибочно удаленные узлы или очистить корзину вручную.

### 19. Улучшение алгоритма перетаскивания и захвата в родителя
В `NodeManager.onSelectedNodesMoved` логика поиска родителя опирается на прямоугольник `overRect` с жестко зашитыми смещениями (`-0.6 + i * 0.01`). Заменить эвристику на прозрачный индикатор места вставки (drop-indicator bar), показывающий точное место, куда встанет узел при отпускании.

### 20. Изоляция субмодуля `_base`
Оформить зависимости из `_base` как локальный npm-пакет рабочего пространства (`packages/base`) вместо прямого импорта через относительные пути и submodule, упростив CI/CD и развертывание на Vercel/Docker.

## 4. Топ-10 рекомендаций по развитию функционала (Features)

### 1. Telegram Quick Capture & Интерактивный бот
- Отправка боту текстовых сообщений, голосовых заметок (с расшифровкой через Whisper/STT) или скриншотов -> автоматическое создание нод в разделе «Входящие» текущего пользователя.
- Интерактивные кнопки подтверждения выполнения задач прямо из Telegram.

### 2. Двусторонние ссылки (`[[Wiki-Links]]`) и граф знаний
- Возможность ссылаться на любые другие ноды и страницы через синтаксис `[[Название]]`.
- Боковая панель обратных ссылок (Backlinks), показывающая, в каких контекстах и фреймах упоминается текущий узел.

### 3. Rich Text, чекбоксы и теги
- Поддержка быстрого форматирования: `**жирный**`, `*курсив*`, ` `код` `, зачеркнутый текст.
- Интерактивные чекбоксы `[ ]` / `[x]` для списков дел с зачеркиванием выполненного пункта.
- Теги `#работа`, `#срочно` с автодополнением и быстрой подсветкой.

### 4. Календарный вид и Timeline (визуализация `repeatMode`)
- Специальный режим отображения или подфрейм-календарь, где задачи с установленными датами повторения раскладываются по дням недели и временной шкале.

### 5. Быстрый поиск и командная палитра (`Ctrl+K` / `Cmd+K`)
- Глобальный нечеткий поиск (Fuzzy search) по заголовкам всех нод на всех досках.
- Быстрый переход к ноде с центрированием и плавным зумом камеры на нее.

### 6. Экспорт и импорт данных (Markdown, OPML, JSON)
- Экспорт любой ветки или всей доски в стандартный Markdown-аутлайн, OPML или JSON.
- Бесшовный импорт из Notion, Obsidian, WorkFlowy, Logseq.

### 7. Миникарта холста (Minimap) и пространственные закладки
- Полупрозрачная интерактивная миникарта в углу экрана с прямоугольником видимой области (viewport) для мгновенной навигации по гигантским доскам.
- Сохранение закладок/видов (Bookmarks): быстрое переключение между фреймом «Работа», фреймом «Личное» и архивом по горячим клавишам.

### 8. Совместная работа в реальном времени (Multiplayer Canvas)
- Возможность поделиться доской по ссылке (только чтение или редактирование).
- Отображение курсоров других пользователей на доске и подсвечивание узлов, редактируемых в данный момент.

### 9. Смарт-фильтры и фокус-режим (Focus / Hoist Mode)
- Возможность «провалиться» в любую ноду (Zoom-in / Hoist, как в WorkFlowy): выбранный узел временно становится корнем экрана, скрывая все постороннее для максимальной концентрации.
- Фильтрация холста по тегам, цветам и статусам без разрушения координат.

### 10. Встроенный AI-ассистент на узлах
- Интеграция с LLM прямо в контекстном меню ноды:
  - *«Разбить на подпункты»* (генерация дочернего списка шагов).
  - *«Суммировать дерево»* (краткая выжимка по всем дочерним узлам фрейма).
  - *«Переформулировать как задачу»*.
